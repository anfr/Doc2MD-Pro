Doc2MD Pro

Documentation complète — Convertisseur de documents (PDF, Excel, Word) vers Markdown optimisé pour les LLM et les pipelines RAG.

Version : 1.2.0 (Dark Pro)  •  Python : 3.10+  •  Licence : MIT

Chapitre 1 — Logique métier

Cette première partie décrit ce que fait l'application et pourquoi, indépendamment de la façon dont c'est codé. Elle s'adresse aux utilisateurs qui veulent comprendre le comportement de l'outil, ainsi qu'aux développeurs qui souhaitent faire évoluer les traitements.

1.1 — Le pipeline global

Le traitement d'un fichier suit toujours la même chaîne, quel que soit son format d'origine :

Source
PDF / XLSX / DOCX
→
Extraction
markitdown / pandas / OCR
→
Nettoyage
optimiser_markdown
→
Enrichissement
métadonnées
→
Sortie
.md / .jsonl chunké

Chaque étape est optionnelle (sauf l'extraction) et contrôlable depuis l'interface via des cases à cocher. L'utilisateur peut ainsi produire un Markdown brut ou un Markdown "prêt pour RAG" selon ses besoins.

1.2 — Haute Performance (Multiprocessing)

Pour traiter de gros volumes de fichiers (ex: 100 PDF en une fois), l'application utilise le module concurrent.futures.ProcessPoolExecutor de Python.

Au lieu de traiter les fichiers un par un de manière séquentielle, l'application crée un "pool" de processus (par défaut, le nombre de cœurs de votre processeur). Chaque fichier est envoyé à un processus libre, qui s'occupe de l'extraire, de le nettoyer et de l'écrire sur le disque de manière totalement indépendante.

Performance : Sur un PC équipé d'un processeur 8 cœurs, un lot de 100 fichiers peut être traité jusqu'à 8 fois plus vite par rapport au mode séquentiel, tout en gardant l'interface utilisateur fluide.

1.4 — Métadonnées

Chaque fichier Markdown généré reçoit un front-matter YAML en tête, contenant des informations exploitables par un pipeline RAG ou par un LLM :

---
source: "Impératif présent.pdf"
type: pdf
doc2md_version: 1.2.0
converti_le: 2026-11-09T17:36:19
mots: 2345
tokens_estimes: 1902
---

Ces champs permettent notamment de filtrer les documents par source dans une base vectorielle, et d'estimer la taille du contexte avant envoi à un LLM.

1.5 — OCR (Récupération de PDF)

Les PDF scannés (images de texte) ou dont la police est corrompue produisent souvent un texte vide ou illisible lors d'une extraction classique.

L'application intègre une option OCR (Reconnaissance Optique de Caractères). Lorsqu'elle est activée, le moteur ne se contente plus de lire le flux texte du PDF : il convertit chaque page en image haute résolution (300 DPI) et utilise le moteur Tesseract pour extraire le texte visuel. C'est plus lent, mais cela permet de récupérer des documents perdus.

Prérequis : L'OCR nécessite l'installation du logiciel Tesseract sur le système hôte, ainsi que les bibliothèques Python PyMuPDF, pytesseract et Pillow.

1.6 — Smart Chunking (RAG)

Les bases de données vectorielles (Pinecone, Qdrant, Chroma) et les modèles d'embedding ont une limite de taille de contexte. Envoyer un document entier de 200 pages sur une seule ligne fait échouer l'indexation.

L'application intègre un algorithme de Découpage Intelligent (Smart Chunking). Au lieu de couper le texte brutalement, il :

  1. Détecte les titres Markdown (#, ##, ###) pour créer des blocs logiques.
  2. Découpe le texte en morceaux d'environ 1500 caractères (paramétrable).
  3. Applique un chevauchement (overlap) de 200 caractères entre chaque morceau, pour que le modèle d'embedding conserve le contexte entre deux phrases coupées.

Le résultat est un fichier .jsonl où chaque ligne représente un chunk, avec son titre d'appartenance et son nombre de tokens estimés.

1.7 — Heuristique Excel (Le problème des grilles)

Les fichiers Excel ne sont pas tous des bases de données. Il peut s'agir de tableaux de bord, de formulaires, ou d'emplois du temps. pandas détruit ces structures visuelles s'il est utilisé de manière aveugle.

Doc2MD Pro intègre un moteur heuristique qui analyse la structure du fichier selon 4 indices :

  • Densité : Si moins de 45% des cellules sont remplies, c'est probablement un document visuel.
  • En-tête : Si la première ligne est vide ou incomplète, ce n'est pas un tableau de données.
  • Texte Vertical : Détection des cellules pivotées à 90° (souvent utilisées dans les emplois du temps).
  • Colonnes : Si les colonnes ne contiennent pas des types de données homogènes.

Selon le score obtenu, l'application choisit automatiquement entre le mode Données (tableau classique) et le mode Visuel (préservation de la mise en page). L'utilisateur peut aussi forcer le mode via le menu déroulant.

1.8 — Mode Sémantique (Optimisé IA)

C'est la fonctionnalité phare de la version 1.2.0. Si l'utilisateur choisit le mode Sémantique pour un fichier Excel, l'application ne génère pas un tableau Markdown avec des trous. Elle analyse la grille et la transforme en un texte linéaire, hiérarchisé et contextualisé.

Le moteur effectue plusieurs opérations :

  1. Fusion des en-têtes : Détecte que la colonne C est "Lundi" et que la ligne suivante indique "Groupe 4", pour créer un en-tête unique : Lundi (Groupe 4).
  2. Forward Fill (Propagation) : Si une heure (ex: 08:30) est écrite en colonne B, elle s'applique à toutes les matières en dessous jusqu'à la prochaine heure.
  3. Détection des pauses : Les lignes comme "Récréation" deviennent des titres de section (### 🕒 Récréation).
  4. Capture du pied de page : Les signatures (Professeure, Directeur) sont extraites dans une section dédiée.

Le résultat est une suite de blocs ### avec des listes à puces. Exemple :

### Matinée - 08:30:00
- **Lundi (4)** : Math 60'
- **Lundi (5+6)** : Math 60'
- **Mardi (4)** : Activités de la vie scolaire 60 min

C'est exactement ce qu'un modèle RAG attend pour indexer et retrouver l'information de manière fiable.

1.9 — Vérification qualité

Avant d'écrire le fichier de sortie, une vérification détecte les cas suspects :

  • Sortie vide : Le PDF est corrompu, protégé ou vide.
  • Sortie courte (< 500 caractères pour un PDF) : Le PDF est probablement un scan sans OCR.

Les avertissements n'empêchent pas la génération du fichier, mais sont journalisés et listés dans le bilan final pour que l'utilisateur puisse réagir (ex: activer l'OCR et relancer).

Chapitre 2 — Architecture technique

L'application suit le principe de séparation des responsabilités. Chaque module a une mission unique et ne connaît que ce dont il a besoin. Cette architecture facilite les tests unitaires, l'ajout de formats ou le remplacement de l'interface graphique.

2.1 — Vue d'ensemble

MarkAIStudio/
├── main.py                 → point d'entrée
├── version.py              → version centralisée
├── config.py               → constantes et regex
├── utils.py                → outils génériques
├── core/                   → logique métier (sans UI)
│   ├── __init__.py
│   ├── converter.py        → conversion brute (OCR + Heuristique Excel)
│   ├── optimizer.py        → nettoyage, chunking et métadonnées
│   └── processor.py        → orchestration multi-processus
└── ui/
    ├── __init__.py
    └── app.py              → interface CustomTkinter (Dark Pro)

2.2 — version.py

CONFIG Rôle : Source unique de vérité pour la version

Contient une seule ligne : __version__ = "1.2.0". Ce numéro est lu dynamiquement par l'interface, les logs et les métadonnées YAML pour éviter toute incohérence.

2.3 — config.py

CONFIG Rôle : centraliser les constantes et regex

Aucune logique. Définit toutes les valeurs modifiables de l'application, les extensions valides, les limites d'extraction Excel, les seuils de l'heuristique, les valeurs par défaut du chunking, et les expressions régulières précompilées.

2.4 — utils.py

CORE Rôle : outils génériques réutilisables

Contient des fonctions pures comme estimer_tokens, est_fichier_ignorable, et la classe Preferences qui gère la sauvegarde des choix de l'utilisateur dans un fichier JSON local.

2.5 — core/optimizer.py

CORE Rôle : transformer le Markdown brut en Markdown optimisé

Ce module contient des fonctions pures (input texte → output texte) sans aucun effet de bord.

Fonctions clés

  • optimiser_markdown(md) : Nettoie les artefacts (ligatures, puces, pages).
  • ajouter_metadonnees(md, source) : Ajoute le front-matter YAML avec la version.
  • verifier_qualite(md, source) : Détecte les PDF scannés ou vides.
  • decouper_markdown(md, max_chars) : Découpe intelligemment le Markdown en chunks avec chevauchement pour le RAG.

2.6 — core/converter.py

CORE Rôle : convertir un fichier source en texte brut

Encapsule markitdown (PDF/DOCX), pandas (Excel) et pymupdf + pytesseract (OCR).

Nouveautés

  • convertir(path, use_ocr=False, excel_mode="Auto") : Point d'entrée qui gère l'aiguillage.
  • _detecter_mode_excel(df) : Analyse la structure (densité, en-tête, texte vertical) pour choisir entre mode "Data" et "Visuel".
  • _extraire_semantique_excel(df) : Le cœur de la v1.2.0. Transforme une grille 2D en texte linéaire avec en-têtes fusionnés, propagation des heures, pauses et pied de page.

2.7 — core/processor.py

CORE Rôle : orchestrer le traitement par lots (Multiprocessing)

Ce module ne touche jamais à l'UI. Il communique via des callbacks passés au constructeur : log, progress, finish.

Le Multiprocessing

Le traitement utilise concurrent.futures.ProcessPoolExecutor.

with concurrent.futures.ProcessPoolExecutor(max_workers=max_workers) as executor:
    futures = {executor.submit(_worker_convertir, tache): tache for tache in taches}
        for future in concurrent.futures.as_completed(futures):
        res = future.result()
        ...

La fonction _worker_convertir tourne dans un processus isolé et reçoit l'option excel_mode pour adapter la conversion.

2.8 — ui/app.py

UI Rôle : interface graphique (CustomTkinter - Dark Pro)

Ne contient aucune logique métier. Toute action est déléguée au BatchProcessor.

Design System

L'interface utilise des couleurs sombres, une Toolbar avec le logo, la version, et des boutons d'action (Aide, Sortie, À propos). La sidebar est défilante pour ne jamais perdre d'options.

Fonctionnalités UI

  • Menu déroulant Excel : Permet de choisir entre Automatique, Visuel, Données et Sémantique.
  • Guide d'utilisation intégré : Une fenêtre d'aide avec un dictionnaire des termes IA (RAG, Chunking, OCR...).
  • Bouton "Sortie" : Ouvre directement le dossier de destination dans l'Explorateur Windows.
  • Gestion de l'état : Le bouton "Lancer" devient rouge "Annuler" pendant la conversion, et gris quand aucune source n'est choisie.

2.9 — main.py

Point d'entrée minimaliste. Il importe multiprocessing, appelle freeze_support() (obligatoire pour PyInstaller), instancie la classe MarkdownConverterApp et lance la boucle principale Tkinter.
